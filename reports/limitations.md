# Limitations and next gates

1. Six separate demo workflows are inactive: mock showcase, protected Intake Preview, protected Intake pipeline draft, mock Test Runner, native JEV Evaluation Core and private Slack sender. The Intake draft is wired to core, Sheets and a preview branch, but it cannot complete a valid enquiry while the JEV gate and Google OAuth remain closed. Invalid-input routing was verified. The public template uses placeholders instead of private workflow/sheet IDs, and no credential-bearing raw export is public.
2. The Google Sheets action credential is present but not authorized. The existing trigger credentials are a different type. n8n must complete Google authorization, then write and read a labelled setup row in the private demo sheet before storage can be marked tested.
3. After the user authorised costs, one native JEV smoke attempt returned HTTP 403 `customer_verification_required`: the Gateway account requires a credit card on file even to unlock free credits. No JEV answer, measured usage or charge was reported. The n8n HTTP credential is unbound and the core's live gate remains closed. No live JEV performance can be claimed.
4. Five MOCK Slack previews exist, but no webhook message was sent. The inactive private sender has a closed approval gate, validated and tested to emit no send items. Delivery and receipt still require one combined approval for five messages plus one summary.
5. Idempotency, concurrent duplicate prevention, lost-response recovery, Sheets write failure and unknown Slack delivery have not been implemented or proven end to end. The current Intake draft uses a simple Sheets append after evaluation and is not safe for parallel duplicate submissions. Keep it inactive until this is resolved.
6. The dataset and policy were authored for this fictional portfolio use. Labels are not sales-team validated, scores are not win probabilities, and no real ROI or production readiness is implied.
