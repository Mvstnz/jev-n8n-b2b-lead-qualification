# n8n workflow sources

`mock-showcase.sdk.js`, `intake-preview.sdk.js`, `test-runner.sdk.js`, `evaluation-core.sdk.js` and `intake-pipeline.template.sdk.js` are portable n8n Workflow SDK source built by `tools/`. They contain no runtime credential IDs or secrets. All five passed MCP validation and were created as **inactive** workflows on the target n8n instance on 24 September 2026. The bound Intake source was generated privately with the Evaluation Core and spreadsheet IDs.

The mock showcase processed DEV-01, DEV-02, DEV-03, DEV-07 and DEV-09 with hand-authored typed answers and produced five `PREVIEW_ONLY` Slack texts. It makes no HTTP, Sheets or Slack request. The Intake Preview accepted one valid synthetic form input. The 13-node protected Intake pipeline rejected a negative budget without side effects; then it completed five distinct synthetic forms through SHA-256 fingerprinting, Google Sheets duplicate lookup, live JEV, fixed scoring, Sheets append, Slack preview and receipt. Four of the five live routes matched authored expectations; DEV-03 went to NEEDS_REVIEW instead of WARM. Two serial replays returned stored receipts without JEV or append. The persisted Sheet rows were independently read back. The separate Test Runner processed 30 cases three times with stored mock answers and reported 90/90 authored-route agreement; it makes no live calls or writes.

The public Evaluation Core source is fail-closed. Its private n8n instance version was enabled for the integration test and has a temporary authorization header in its HTTP node because the available n8n MCP cannot create credentials. Replace that header with a native n8n HTTP credential before operational activation; never export the private workflow to this repository. The dedicated Vercel key has a USD 1 non-resetting budget within USD 5 free credits. All six demo workflows remain inactive.

These sources are not raw n8n exports. Operational workflow IDs and links are intentionally absent from the public repository. A sixth private inactive Slack sender is not exported because its HTTP node contains an operational webhook URL. Its closed approval gate was tested, then one approved six-message MOCK batch was sent and verified in Slack; the gate was relocked. The separate [native HTTP adapter](../reference/jev_adapter.py) is offline tested and has validated a successful real JEV response. See [integration evidence](../reports/integration-tests.md) and [limitations](../reports/limitations.md).
