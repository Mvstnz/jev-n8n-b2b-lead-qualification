# n8n workflow sources

`mock-showcase.sdk.js`, `intake-preview.sdk.js`, `test-runner.sdk.js` and `evaluation-core.sdk.js` are portable n8n Workflow SDK source, built by the scripts in `tools/`. They contain no runtime credential IDs or secrets. On the target n8n instance (24 September 2026), all four passed MCP validation and were created as **inactive** workflows.

The mock showcase was executed manually. It processed DEV-01, DEV-02, DEV-03, DEV-07 and DEV-09 with hand-authored typed answers and produced five `PREVIEW_ONLY` Slack texts. It makes no HTTP, Sheets or Slack requests. The intake preview uses n8n user authentication and rejects unauthorized fields and malformed form values. One valid synthetic form-trigger execution succeeded. It does not yet invoke JEV or save a lead. The Test Runner processed 30 cases three times with identical hand-authored answers and reported 90/90 authored-route agreement; it makes no live calls or writes. The Evaluation Core contains a native JEV HTTP node, response adapter and policy gate, but its credential is unbound, its live gate is closed and it has not processed a JEV response.

These sources are not raw n8n exports and cannot alone demonstrate a completed end-to-end pipeline. The operational workflow IDs and links are intentionally kept out of the public repository. A fifth inactive workflow, `JEV B2B Demo | Slack Sender - Private`, is deliberately not exported here because its n8n HTTP node contains an operational webhook URL. Its closed approval gate was tested with no send. The separate Python [native HTTP adapter](../reference/jev_adapter.py) is offline tested; its first authorised native request returned 403 before model evaluation. The Google Sheets action OAuth credential still needs its Google authorization step; JEV runtime credential binding and Vercel account verification remain open. See `reports/integration-tests.md`.
